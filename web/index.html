01

下载与 Cookie

Q创建任务的表单在哪里？

现象：工作台不再一直显示创建任务的长表单。
原因：创建入口已集中到弹窗，并会按素材来源只显示当前需要的字段。
操作步骤：点击顶部或空状态中的“新建翻译任务”，先选择“YouTube / URL”或“上传已有字幕”，再填写对应字段；关闭后再次打开，当前页面内已填写的内容仍会保留。
跨盘上传失败：旧版在系统临时目录与任务目录位于不同盘符时可能出现 WinError 17；更新并重启工作台后重新上传。新版会先在任务目录暂存，再原子写入，无需修改系统 TEMP。

Q为什么首次打开时模型和接口都是空的？

现象：首次使用没有预选模型或供应商接口。
原因：模型与接口决定字幕发送到哪里，工作台不会替你做供应商选择。
操作步骤：在新建 URL 任务时填写 API Base URL、API Key 和模型名称。普通配置会跨程序重启恢复；Key 只显示“已安全保存”，不会回显原文。

Q启动后提示“工作台会话无效 / 任务列表读取失败”

现象：刚启动就看到任务列表读取失败或会话无效。
原因：服务重启或浏览器会话失效后，需要重新建立本地安全连接；这不表示任务丢失。
操作步骤：更新到当前版本后重新从桌面启动器打开。工作台已运行时，重复双击启动器会重新打开现有页面，不会再启动一个冲突的服务；只有现有实例不可用时才创建新实例。看到“会话已失效”时，先使用启动器新打开的页面；若仍失效，关闭工作台服务后重新启动。新页面已恢复后，旧页可点“重新连接”刷新并保留当前任务地址；未成功的保存或导出不会自动重放。

Q错误码是 operation_blocked / cancelled / interrupted，任务卡住不能操作

现象：失败横幅显示 operation_blocked（任务当前状态不允许执行此操作）、metadata_update_error（任务信息更新失败）、cancelled（任务已取消）或 interrupted（服务重启中断了任务）。
原因：这四类都不是模型或字幕的问题，而是任务状态与页面显示不同步：任务可能正在运行、已经被取消，或者工作台在下载/翻译途中被重启，页面上仍停留在旧状态。cancelled 与 interrupted 的产物都会保留，已经写入 manifest 的批次不会重复付费。
操作步骤：先刷新任务列表或重新打开工作台页面，确认真实状态后再操作。interrupted 会复用已保存的接口、模型和安全 Key，点“继续失败批次”即可；只有凭据被接口拒绝时才需要在设置页更新。cancelled 如果确实不再需要，直接删除任务即可。

QYouTube 提示 429 或“确认不是机器人”

当前 VPN 出口或匿名会话被 YouTube 限流。先换节点；仍失败就在当前任务点击“更换 Cookie 并重试”，选择自动读取 Google Chrome，或直接粘贴 Netscape cookies.txt 内容。不要连续无认证重试，也不需要删除并重建任务。

Q提示“当前清晰度不可用，已自动降级重试”

现象：下载日志出现降级提示，任务仍继续。
原因：所选清晰度在该视频上没有可用格式（常见于低热度视频或刚上传的视频），下载器会自动退回“单一流”方式：画质可能从 1080p 降到 720p 左右，但保证有音轨，流程不中断。
操作步骤：无需处理，等任务正常完成即可；若成品画质确实不足，删除任务后选更低的目标清晰度重建一次，通常能直接命中可用格式。

Q提示“YouTube 会话不匹配，已改用匿名方式重试”

现象：带 Cookie 下载时日志出现该提示，随后任务继续。
原因：YouTube 检测到 Cookie 与当前网络出口不匹配（典型报错 page needs to be reloaded），此时带着 Cookie 反而更容易失败；下载器会自动摘掉 Cookie，用匿名身份重试一次。
操作步骤：无需处理。Cookie 文件不会被修改或删除，只是这一次重试不使用它；若匿名重试仍失败，会按普通下载失败处理并给出具体原因。

Q提示“yt-dlp 合并异常，已改用 ffmpeg 本地合并”

现象：下载日志出现该提示，任务仍继续并产出视频。
原因：yt-dlp 在把音视频合成为一个文件时自身崩溃（已知触发点：'NoneType' object has no attribute 'lower'）。下载器会改用本机 ffmpeg 直接合并已下载的音视频分片，不重新下载。
操作步骤：无需处理。若提示后仍然失败，说明本机缺少 ffmpeg 或分片本身不完整，按普通下载失败的提示处理即可。

Q为什么会触发机器人验证，怎样尽量避免？

YouTube 会按公网 IP、访客或账号会话以及请求频率判断流量。多人共用的 VPN 出口、短时间反复创建或重试任务、浏览器验证和下载使用不同 IP，都更容易触发。建议使用稳定且人数较少的节点；一个任务失败后不要马上连续重试；先在同一 VPN 节点下用 Chrome 正常打开 YouTube并完成验证，再让应用读取 Chrome；Cookie 只在确实需要时使用。应用已把下载任务串行处理，避免多个视频同时轰击 YouTube，但无法保证永远不触发平台风控。

Q第一次创建任务一定要提供 Cookie 吗？

不需要。未被限流时选择“匿名下载”即可；需要登录验证时，可让应用自动读取 Google Chrome，或选择“直接粘贴 Cookie 文本”。应用会记住认证方式，但不会保存 Cookie 正文。

Q自动读取 Google Chrome Cookie 失败

Windows 可能锁住 Chrome 的 Cookie 数据库。完全退出 Chrome，检查任务管理器里没有残留进程再试；不想关闭浏览器时，改选“直接粘贴 Cookie 文本”，从剪贴板读取 Netscape cookies.txt 内容。

QCookie 会不会被保存或上传？

现象：粘贴 Cookie 后，担心登录凭据留在便携目录、云盘或任务备份中。
原因：Cookie 只交给项目当前 Python 环境中的 yt-dlp 请求 YouTube，不会写入任务 JSON、技术日志、下载产物或 download/<任务>。排队时正文只在进程内存；下载真正开始时才在当前 Windows 用户专属、关闭继承权限的本地临时目录生成随机文件。成功、失败、取消、暂停和强制停止都会删除并清空；异常断电留下的旧版或临时文件会在下次启动恢复任务前清理。
操作步骤：优先匿名下载；确实需要登录时再使用 Chrome 或粘贴 Cookie。暂停、重启或崩溃后必须重新粘贴，系统不会为了方便而保留凭据。Cookie 等同登录凭证，请勿分享。

Q下载走代理，模型翻译也会走吗？

现象：下载或模型请求无法连接本机代理。
原因：首次固定填写 http://127.0.0.1:7890，同一地址会传给下载与翻译阶段，并由本机设置跨程序重启恢复。
操作步骤：代理工具监听其他地址时直接修改并保存；不使用代理时可以清空。代理字段不得包含用户名或密码。

Q从网址创建任务时下载必失败，只提示“素材下载或处理失败”

现象：用 start_web.bat 启动工作台后，所有“YouTube / URL”任务都在下载阶段失败，任务只显示“素材下载或处理失败”。
原因：旧版下载子进程用 -I 隔离模式启动，会忽略启动环境注入的依赖路径；当首选运行环境的 yt_dlp 位于 .runtime_deps 而不是自带 site-packages 时，下载进程因此找不到 yt_dlp 模块。
操作步骤：更新并重启工作台。新版让下载子进程与启动环境使用同一套依赖布局，并在缺失模块时把失败原因明确标为“缺少 yt_dlp 模块”。若重启后仍提示缺少模块，请运行项目根目录的 install_web.bat 重新安装依赖，再重启工作台。

02

字幕与 Whisper

Q成品里为什么还有几条没翻译的英文？

现象：任务完成后任务卡提示“成片含 N 条未翻译英文句”；下载的字幕里个别条目仍是英文原文。
原因：来源字幕的 ASR 质量或模型漏译会让极少数句子没有中文译文；[笑声]、[掌声] 这类括号音效标注属于设计内保留，不计入未翻译。
操作步骤：进入“风险审校”页逐条确认或补译，确认全部必审条目后导出 final.reviewed.zh.srt。如果未翻译条目很多，通常是来源字幕质量不足，建议更换来源或补一份剪映/Whisper 字幕再重翻。

Q只下载了字幕的任务，之后还能补充剪映/Whisper 第二源吗？

现象：创建任务时没有下载视频（无法本地 Whisper），质量评估提示建议补充第二源证据。
原因：自适应与 Whisper 策略需要视频文件，只下字幕的任务只能用 YouTube 字幕作证据；但任务完成或失败后随时可以补上传剪映 SRT。
操作步骤：打开该任务的详情页，展开“补充剪映字幕（可选第二源证据）”，上传剪映导出的源语言 SRT；任务会回到“待翻译”状态，重新点“开始全量翻译”即可用新证据重翻（证据改变会重翻全部批次，不属于断点续跑）。

Q便携版提示没有 FFmpeg 或 Whisper，还能翻译吗？

现象：状态栏提示缺少 FFmpeg 或本地 Whisper，视频下载和自适应识别选项会自动停用。
原因：基础便携版只内置安全运行翻译与获取 YouTube 字幕所需的组件，不捆绑体积很大的视频转码器和 GPU 识别模型。封面会保留 YouTube 原始图片格式，VTT 字幕由工作台在本机转换为 SRT，不需要 FFmpeg。
操作步骤：可以直接上传已有 SRT，或选择有对应源语言字幕的 YouTube 视频继续翻译。需要下载视频或生成“黑框白字2”带字幕视频时，请自行安装带 libass 的 FFmpeg 和中文字体并重启工作台；需要无字幕视频识别时，再安装可选 Whisper 环境。API Key 的安全保存方式不受这些可选组件影响。审校页显示“真正待处理 0”并已生成已审校字幕后，自动处理完成的条目不会再次拦截视频生成。最后一条必审项保存后显示“审校已完成”，点击“生成交付文件”即可生成黑框白字2 MP4；同一区域可下载已审校 SRT、查看进度、取消或重试，并打开当前任务目录。
命令行试运行异常：旧版在非 UTF-8 代码页打印中文性能报告时可能出现 UnicodeEncodeError，SRT 虽已写出但进程报错；更新后重跑即可。新版会将当前代码页无法表示的字符转义输出，无需修改字幕文件。

Q日语或韩语任务提示源语言不匹配，或为什么音乐提示没有进入审核？

现象：上传的 SRT 与选择的英语、日语或韩语不一致时，任务会在创建前拒绝；[音楽]、[음악]、[拍手]、[박수]、（笑）、(웃음) 和 ♪ 不再显示为空译文风险。
原因：任务的源语言必须与字幕正文一致，不能只靠文件名或下拉框声明。纯音乐和音效标记不包含需要翻译的对白。
操作步骤：请上传与任务源语言一致的人工/自动字幕或 Whisper 结果；多语言混合视频先导出对应语言轨道。音乐标记无需人工处理；标记旁有对白时请保留正文。

QWhisper 到底什么时候会运行？

高级设置选择“自适应”时，YouTube 源语言字幕缺失、与任务语言不一致或质量不足才会运行完整 Whisper；选择“始终使用本地 Whisper”则每次运行。风险复核中的局部 Whisper 只处理需要音频证据的片段。

QWhisper 启动时提示“WinError 5：拒绝访问”

系统可能禁止读取某个可选 Python 或 NVIDIA 目录。该目录并不一定是当前 Whisper 真正使用的环境；旧版本在扫描 CUDA DLL 时会因此中断。更新并重启工作台后，程序会跳过无权访问的可选目录，继续检查项目运行环境。若随后仍提示缺少 cuDNN，请在“技术日志”确认实际缺少的 DLL，再按日志安装对应 CUDA 运行库。

QYouTube 没有任务源语言字幕怎么办？

在高级设置中选择“自适应”并保持“下载视频”开启，系统会转用本地 Whisper。仅 YouTube 模式没有字幕时会直接失败，因为它没有可用的英文来源。

Q为什么必须上传剪映字幕，怎样直接打开剪映？

现象：旧英语任务可能仍停在“等待上传剪映主字幕”；日语和韩语自动多源任务无需剪映也能继续。
原因：新版会比较 YouTube、Whisper 与可选剪映字幕，只有质量更高的来源才成为主源；浏览器启动桌面程序仍需本地工作台查找剪映专业版/CapCut。
操作步骤：需要补充剪映证据时点击“打开剪映”，识别当前任务源语言并导出 SRT 后上传。找不到剪映时可设置 SUBTITLE_CAPCUT_EXECUTABLE；不上传时继续使用自动选择的同语言来源。

Q为什么出现 [Music]、空字幕或重复句？

现象：字幕中出现 [Music]、空行或重复句；旧版本也可能在 Round 1 显示“模型连续漏译字幕”。
原因：YouTube 滚动字幕和 ASR 会产生舞台标记与重叠窗口；旧版没有把带主播前缀的 >> [music] 识别为纯音乐，模型按要求返回空译文后又被漏译校验拦截。
操作步骤：更新并重启工作台，打开失败任务后重新运行同一任务即可复用已经完成的批次。最终导出会清理音乐标记和相邻重复；极短字幕中的有效内容会先合并到相邻字幕，纯标记和空内容才会被清理。技术产物或旧风险记录仍可能保留原始证据。

Q为什么普通英文单词会触发“模型连续漏译字幕”？

现象：句子本身已经翻译完整，但日志反复要求补译 Window、Level、Slow、Burn、Launch 等词。
原因：旧版把所有命中的术语都当成必须逐字出现的硬术语；这些词在普通口语中并不总是游戏 UI 名称。
操作步骤：更新并重启工作台，再对失败任务使用续跑。新版仍会把这些译名作为提示，但只有人物、地点、正式多词术语或明显 UI 形式才会触发阻断重试；已经成功的批次会从 manifest 恢复。

Q为什么字幕和说话时间对不上？

现象：字幕比人声晚出现、说完后仍停留很久，或有的句子一闪而过。
原因：YouTube 滚动字幕会把同一句拆成多个窗口；只合并文字会留下异常的窗口首尾时间。当前版本会识别十秒以上的异常字幕，在自适应模式下保留 YouTube 英文文本、采用 Whisper 的语音时间，再把校准后的时间传给中文成品；Whisper 不负责替换正文翻译。
操作步骤：重启工作台后，用“自适应”来源策略重新创建任务。旧任务已经写入原时间轴，不会自动改写；如需修复旧成品，请保留视频和过程文件后重新创建任务。

Q为什么一句话会只剩半句或几个字？

原因通常是 YouTube 滚动字幕把句尾单独切成约 10 毫秒的片段，旧版本会把它误当噪声删除。当前版本会在翻译前合并有效片段，并在残句较多时自动请求 Whisper 作为第二证据；Whisper 补充失败但 YouTube 字幕仍可用时，任务会继续而不是整体失败。旧任务不会自动重写已经生成的译文，请重新创建同一链接并重新运行，再下载新的最终字幕。

Q为什么韩语/日语任务会报“时间轴未递增”或“不合理重叠”而失败？

现象：上传 YouTube 自动字幕（韩语/日语）后任务失败，提示“字幕 #N 时间轴未递增”或“与前一条发生不合理重叠”。
原因：YouTube 自动字幕是滚动窗口结构：相邻行时间上重叠约一半（窗口滑动），但文本是上一行的延续而不是重复。旧版本只按时长判断是否合并，滚动行被跳过，重叠的时间轴又传染给最终回填字幕，交付检查因此拒绝。
操作步骤：更新并重启工作台后重新创建同一任务。当前版本会先把重叠的滚动行裁剪为首尾相接，再按完整句合并，最终字幕不会出现重叠；旧任务不会被自动改写，请重新创建任务。

Q错误码 source_unreliable：素材质量不足，请更换来源

现象：失败横幅显示 source_unreliable，原因是“素材质量不足，请更换来源或重新上传”。任务没有进入翻译阶段。
原因：取到的英文/日文/韩文字幕无法作为可靠翻译证据：可能是自动字幕残句过多、时间轴大面积重叠、正文与所选源语言不一致，或者整份字幕几乎是空的。此时继续翻译只会花掉模型费用换来不可用成品，所以质量门禁会在翻译前拦下。
操作步骤：不要在同一份素材上反复重试。换一个来源：改用 YouTube 人工字幕轨道、把来源策略切到“始终使用本地 Whisper”，或者自己上传一份与源语言一致的 SRT。确认新素材在预览里能读到完整句子后再重新创建任务。

日语 → 简体中文

Q创建日语任务时应该选择什么语言？

现象：下载或上传后不确定字幕会按哪种语言处理。
原因：源语言会同时决定 YouTube 字幕、Whisper、术语、翻译记忆和风险复核的规则。
操作步骤：创建任务时把“源语言”选为“日语”，目标保持“简体中文”；不要把英语 SRT 与日语 SRT 放进同一个任务。

QYouTube 没有日语字幕时会怎样？

现象：下载阶段提示没有可用的日语字幕。
原因：日语任务只接受日语人工/自动字幕或日语 Whisper 证据，不能悄悄回退到英语字幕。
操作步骤：保持“下载视频”开启并使用“自适应”或“始终使用本地 Whisper”；若视频本身不是日语，请新建对应语言的任务。

Q日语任务可以补充源语言字幕吗？

现象：任务下载后可以直接翻译，不要求等待额外字幕。
原因：补充的源语言字幕只是可选证据；系统会按语言匹配、碎片率、重复率和时间轴质量自动判断主来源。
操作步骤：通常直接开始翻译；手上有剪映导出的日语 SRT 时，再打开“补充剪映源语言字幕（可选）”并上传。

Q为什么日语人物名即使译对了也会进入审校？

现象：风险页显示人物名需要人工确认，但没有自动重翻。
原因：日语 ASR 的同音人名可能看似合理；系统要求人工确认所有已知人物名，但正确名字本身不是付费 Round 2 的理由。
操作步骤：对照两路日语证据确认后保存即可；只有人名错误、漏译或与其他强风险同时出现时，才需要 Round 2。

Q日语会复用英语术语、提示词或翻译记忆吗？

现象：担心英语任务的人工修订影响日语任务。
原因：术语按源/目标语言保存，翻译记忆按语言对隔离，日语也使用独立提示词和 Round 2 指令。
操作步骤：在“术语库”和“提示词模板”选择日语后再维护内容；旧任务未带语言字段时仍按英语 → 简体中文处理。

Q日语字幕里的假名人名或地名没有命中术语库怎么办？

现象：字幕听到了角色或地点的读音，但术语提示中没有出现对应的简中专名。
原因：日语人工字幕可能使用汉字表记，而 Whisper 和自动字幕通常输出假名；同一个日语专名会同时收录汉字表记和假名读音，避免两种证据因写法不同而漏匹配。
操作步骤：新建或从头重跑任务以使用新版术语快照；仍未收录的专名请在“术语库”选择“日语”后，把汉字表记和假名读音分别添加为两条术语，并填入同一个简中译名。

03

模型与翻译

Q为什么字幕全是“[待翻译]”英文？

这说明旧任务开启了试运行：它只检查流程和生成占位文件，不会调用模型，也不是真正的完成结果。现在工作台已经移除这个容易误触的选项。打开该任务，在详情中输入 API Key 后点击“开始正式翻译”即可复用已下载的视频、YouTube 字幕和 Whisper 结果，无需重新下载；原试运行占位产物会单独备份。

Q为什么 Round 2 有时还不如 Round 1？

现象：Round 2 有时会改动一个与风险无关的词，结果反而不如 Round 1。
原因：Round 2 是针对明确风险的校错器，不是整句重写器。当前版本默认保留 Round 1；相邻字幕会作为只读语境交给 Reviewer，避免把跨字幕才补全的短语误判为多译。系统只自动采用有源语言证据的最小修正，并拦截低置信度、无关重写、新增否定、未修完残句、数字或术语校验失败的候选；如果实体风险没有被实际修正、候选只改了其他语义，也会回退 Round 1 并留给人工复核。唯一的显示兜底是：日语或韩语 Round 1 已确定残留假名/韩文，而 Round 2 给出无源文字的低置信中文候选时，成品可先使用该候选避免残留，但它仍会留在“待我处理”，不会标成已解决或人工确认；普通文本冲突和阅读速度也只供人工比较。
操作步骤：若旧任务里已经出现较差的 Round 2，请先在审校页选择 Round 1；要应用新规则，请重新创建同一链接并重新运行，旧版 Round 2 结果不会继续自动复用。

Q两个模型应该怎么选？

主模型负责全量翻译。Round 2 只处理明确风险；留空时自动沿用主模型，不需要重复填写。

Q为什么跨好几条字幕的半句话更容易译顺了？

现象：快速 Reaction 或滚动字幕会把一句英文拆成多条，逐条翻译容易产生三个中文残句。
原因：旧版本只附带前后各两条，并可能在机械批次边界切断完整句。当前版本会在 Token 硬上限内优先保持临近完整句，提供前后六条局部证据、最近十二条对话记忆，并注入视频标题、频道和全片锁定专名。
操作步骤：新建或从头重跑任务以使用新上下文；旧任务会保留原有 manifest，避免静默改变已经付费生成的译文。

Q页面上的模型费用是怎样估算的？

只有内置价格表能够识别的模型才会估算人民币费用，其他模型显示“暂不估算”。由于任务指标没有区分缓存命中 Token，页面按未命中缓存保守计算；实际扣费仍以接口供应商账单为准。

Q模型为什么会失败或漏回字幕 ID？

现象：技术日志出现 HTTP 400、401/403、429、超时，提示接口地址为空，或模型漏回少量字幕 ID。
原因：正式翻译必须明确填写接口地址，配置区会显示“请求将发送至”哪个主机；远程接口只允许 HTTPS，本机 localhost、127.0.0.1、::1 才可使用 HTTP。401/403 通常是 Key、模型权限或中转站问题；429/超时是限流或线路不稳。为防止恶意接口回显 Key、Cookie、字幕或本机路径，工作台不会保存或显示上游原始错误正文，只保留状态码和本地生成的排查提示。结构异常和漏回 ID 会保留已经有效的结果，只补请求缺失 ID；请求体、任务数量、任务目录空间或实时连接达到本机安全上限时，会在不删除已有任务的前提下拒绝新请求。
操作步骤：确认页面显示的目标主机正确，再检查状态码、模型、接口、代理和请求限制；若看到本机安全上限提示，请先整理旧任务或断开不用的实时页面；修正后在原任务点击“继续失败批次”，不要立即从头重跑。

Q错误码 authentication_error：API Key 无效、已过期或无权访问当前模型

现象：失败横幅显示 authentication_error，任务在预检或第一批停下。
原因：接口拒绝了已保存凭据，或 Key 没有访问当前模型的权限。
操作步骤：在设置页重新粘贴完整 Key 并保存，再在原任务点“继续失败批次”。Key 由 Windows Credential Manager 保存；API、设置 JSON、浏览器存储和任务文件都不会返回或记录原文。若系统安全存储不可用，页面会明确提示仅本次会话有效。

Q错误码 quota_error：API 账户/订阅额度不足

现象：失败横幅显示 quota_error，右侧可能跟着“上游 HTTP 403”或“上游 HTTP 429”。任务在预检或某一批停下，提示“API 账户/订阅额度已用尽”。
原因：部分服务商用 HTTP 403 加 insufficient_user_quota 表达余额不足，另一些订阅制网关（如 opencode）用 HTTP 429 加 GoUsageLimitError 表达周/月额度用尽——这与 authentication_error（Key 无效）是两回事：你的 Key 没问题，是账户/订阅额度用完了，原地重试不会成功，系统也不会对这类失败自动续跑。
操作步骤：到服务商后台充值，或查看订阅额度的重置时间；恢复后回工作台在原任务点“继续失败批次”，已写入 manifest 的成功批次不会重译，只补做失败的那几批。

Q错误码 configuration_error：模型接口配置无效

现象：失败横幅显示 configuration_error，原因是“模型接口配置无效，请检查接口地址和模型名称”。请求根本没有发出去。
原因：接口地址或模型名不合法：地址为空、缺协议头、把浏览器网址当成了 API 地址、带了查询参数或账号密码片段，或者用了 HTTP 访问非本机地址。工作台要求远程接口必须是 HTTPS，只有 localhost、127.0.0.1、::1 这三个本机回环地址允许 HTTP；主机名也要能通过域名合法性校验。
操作步骤：打开设置页，在接口地址输入框点击后从建议列表选择 DeepSeek 官方或 OpenCode Zen 网关，或粘贴完整的 OpenAI 兼容地址（形如 https://…/v1，末尾不要加 /chat/completions）；确认下方“请求将发送至 …”显示的主机正确，再填写模型名。改好后在原任务点“继续失败批次”。

Q错误码 provider_unavailable / api_error / invalid_provider_response：接口暂时不可用

现象：失败横幅显示 provider_unavailable（模型接口暂时不可用）、api_error（模型接口请求失败）、invalid_provider_response（模型接口返回无效内容）或 internal_error，右侧可能跟着“上游 HTTP 429 / 500 / 502 / 503”。
原因：问题在供应商或线路上，不在你的配置：429 是限流，5xx 是接口自身故障，超时是线路不稳；invalid_provider_response 则是接口返回了 200 但正文不是可用的结构化结果。这几类都可能是暂时的。
操作步骤：先等一两分钟再点“继续失败批次”——已经写入 manifest 的成功批次不会重复付费，只会重做失败的那几批。如果连续几轮都失败，换一个模型接口或换成官方直连地址；仍在 429 就调小批次大小、降低并发。不要从头重跑整个任务。

Q错误码 translation_batch_error / batch_processing_error / pipeline_error：批次失败

现象：失败横幅显示 translation_batch_error（翻译批次失败）、round2_invalid_response（Round 2 返回无效结构化结果）、batch_processing_error（批次处理失败）或 pipeline_error（翻译任务失败）。任务已经跑了一段，中途停下。
原因：某些批次在重试预算内仍然没有拿到可用结果，或者返回的结构缺少字幕 ID。这类失败是局部的：其余批次的译文已经写进 manifest，是有效的、已经付过费的产物。
操作步骤：在原任务详情里点“继续失败批次”，系统会复用 manifest 只重做缺失的批次，不要选“从头重跑”。round2_invalid_response 同样只需继续——Round 2 会重做这一批，Round 1 的结果保持不变。如果同一批反复失败，在详情里把失败原因展开看一眼：残留英文、缺必需术语或多次未译会在技术日志里给出具体的批次和字幕 ID。

Q模型一直显示处理中，但没有返回译文怎么办？

现象：技术日志已经显示接口返回 200，但模型持续发送推理片段，几分钟后仍没有完整译文。
原因：opencode.ai/zen/go 一类网关在慢窗口下单次请求可能拖到 2-3 分钟；旧版本 120 秒读超时会在完整译文返回前掐断连接，触发反复重试直到提示“模型接口暂时不可用”。
操作步骤：更新并重启工作台。新版把每次流式请求的读超时与总时限都放宽到 300 秒；超过后会关闭当前连接并只重试当前失败批次，已写入 manifest 的成功批次不会重复付费。仍失败时在原任务点击继续，不要从头重跑。高级用户可用 LLM_STREAM_DEADLINE_SECONDS 调整正数秒数。

Q生成风险后提示“RiskItem object has no attribute get”

这不是模型失败，而是旧版本在“风险对象 → 局部 Whisper”交接处混用了对象和字典类型。模型已返回的 Round 1 与风险快照仍然有效。升级并重启应用后，在原任务重新输入 API Key，点击“继续失败批次”；系统会复用 manifest，从风险处理阶段继续，不要选择“从头重跑”。

Q人名仍然翻错，应该改哪里？

先在术语表添加官方英文与中文，再补充常见 ASR 错拼。新任务中，只要所有有效英文证据命中已知人物名或可靠别名，即使 Round 1 已使用官方译名，也会进入“待我处理”供人工确认；确实译错或疑似未知人名时才调用 Round 2，避免为正确人名重复付费。已有任务的不可变风险快照不会被自动重写，需要重新创建任务才能应用新规则。

Q为什么辅助英文已经识别出人名，却没有进入人工审校？

现象：主英文把人物名听错，但 Whisper 或 YouTube 的辅助英文已出现正确名字，风险页却没有必审卡片。
原因：旧版本只按主英文生成了人物名命中，遗漏了辅助证据中的已知人物名和可靠别名。当前版本会检查所有有效英文证据；已知人物名只加入人工审校，不会单独触发 Round 2。
操作步骤：更新并重启应用后重新创建任务，在“待我处理”中确认人物名；旧任务的风险快照保持不变，不会自动改写。

Q为什么译对的人名也出现在人工审校里？

人物名属于强制人工确认项，因为 ASR 可能把一个名字识别成另一个真实名字，中文译文看起来正确也不代表人物身份正确。正确译名只进入人工列表，不会单独触发 Round 2；出现漏译、错译或疑似未知人名时才让 Round 2 提供修正建议。确认无误后使用“用 Round 1 译文”或直接保存即可。

Q键盘怎样更快审校风险？

现象：使用键盘切换到风险审校页后，焦点以前会停留在侧栏，风险卡也不便连续浏览。
原因：审校页原先主要按鼠标点击设计，缺少进入新页面后的焦点引导与卡片级键盘路径。
操作步骤：点击导航后焦点会进入当前页面标题；在风险卡上按 Enter 或空格进入译文编辑，按上、下方向键切换相邻风险。编辑时保留原有快捷键：1 用 Round 1，2 用 Round 2，Enter 保存。

审校与导出

Q任务详情里的五个标签怎样切换？

现象：选中任务后，原来连续显示的进度、日志、文件和风险被分到 Overview、Pipeline、Log、Files、Risk 五个标签。
原因：详情按用途分区，技术日志可以独立滚动，刷新或实时更新时仍停留在当前标签。
操作步骤：点击标签切换；键盘焦点位于标签时，按左、右方向键切换相邻标签，按 Home 跳到 Overview，按 End 跳到 Risk。选择另一条任务时会回到 Overview。任务列表先显示摘要，文件大小和视频有效性在打开当前任务详情时检查。

Q为什么人工审核条目看起来很多？

“待我处理”只显示会影响交付的强风险；普通双源差异和阅读速度属于参考项，不阻塞最终字幕。可以在风险页切换筛选，不需要逐条处理全部参考项。

Q人工修改会不会自动影响以后的字幕？

现象：保存人工译文后，希望系统逐渐记住习惯，但又担心一次误改污染所有任务。
原因：普通修改现在只进入本机翻译记忆档案，默认不发送给模型。只有你勾选“以后遇到完全相同的英文时，优先沿用这版”，该记录才会被批准；新任务也只在英文证据完全一致且游戏相同时注入，不会按相似句猜测。
操作步骤：在风险卡填写最终译文和修改类型；一般修改直接保存。确认这条译法可重复使用时再勾选“以后沿用”。已完成任务不会被反向重写。

Q怎么把下载目录整理得更清爽？

现象：一个任务目录里同时出现英文来源、Whisper、Round 1/2、manifest、风险 JSON、配置和证据，找字幕、视频和封面时很碍眼。
原因：这些都是用于恢复翻译和人工审校的过程文件，不能直接删除，否则审校记录和排查证据会丢失。
操作步骤：任务完成后，在“下载与存储”点击“整理过程文件”。当前目录只保留 final.zh.srt、已审校时的 final.reviewed.zh.srt、视频和封面；其余文件统一移进“过程文件”子文件夹，文件不会被删除，工作台仍可继续审校和下载。

QAPI Key 和代理凭据会保存在哪里？

现象：填写密钥后关闭并重开工作台，页面只显示“已安全保存”，不再回显原文。
原因：普通配置原子写入当前 Windows 用户的 %LOCALAPPDATA%\PhoebeSubtitleLab\settings.json；API Key 单独保存到 Windows Credential Manager 的 PhoebeSubtitleLab/APIKey。API、设置 JSON、浏览器存储、任务文件和日志都不会得到 Key 原文。
操作步骤：需要更换时在设置页粘贴新 Key 并保存；需要删除时点击“忘记已保存 API Key”。若系统安全存储不可用，页面会提示 Key 仅本次程序会话有效，绝不会退回明文文件。批量重试翻译任务前也需先保存 Key；若尚未配置，工作台会提示到“设置与帮助”填写，任务不会开始重试。

Q为什么旧书签打不开，或者页面提示工作台会话无效？

现象：手动打开旧的 127.0.0.1:8765 地址、复制以前的页面地址，或服务重启后继续使用旧标签页时，工作台无法读取任务。
原因：新版每次启动都会先独占一个随机本机端口，并建立只在当前浏览器会话有效的安全凭据；这样其他本机程序不能仅凭固定端口操作任务或读取字幕。凭据不会写入书签、浏览器存储、日志或任务文件。
操作步骤：关闭旧页面和旧启动窗口，再双击“启动翻译工作台”；只使用本次自动打开的新页面，不要保存本机地址为书签。

Q为什么自动字幕已生成，主按钮却要求先审校？

现象：任务显示已完成，也能看到自动字幕，但主按钮显示“处理必审风险”。
原因：还有人物名、漏译、数字或术语等会影响交付的强风险没有人工确认；自动流程完成不等于可以安全交付。
操作步骤：点击“处理必审风险”，在风险页逐条确认或保存；必审项清零后，页面会显示“下载可交付中文字幕”。如需先查看模型自动结果，可下载“自动版字幕”，但它尚未完成审校。

Q为什么不再生成浏览器真人审核包和指标？

现象：工作台不再提供要求填写审核者姓名、判断和证据的独立页面。
原因：这类页面会把本地审核身份和判断暴露给浏览器，实际收益也不足以抵消隐私风险，因此相关页面、API、审计日志和实时指标已经停用并删除。
操作步骤：继续使用真实视频自动流程和普通任务风险审校即可；应用不会再收集审核者姓名，也不会把机器结果伪装成人工确认。

Q旧的英语质量审核地址为什么打不开？

现象：访问旧地址 /review/english 或旧的审核 API 会返回 404。
原因：该隐私敏感功能已经完整退役，页面、脚本、样式、后端存储和本地审核记录均已删除；普通字幕翻译流程不依赖它。
操作步骤：不需要恢复旧页面；直接创建英语视频任务。需要判断质量时，只查看任务自己的字幕和技术指标，不填写或保存审核者身份。

Q怎样在风险审校页切换任务？

现象：打开风险审校后，不确定正在审哪个任务，或想审另一条已完成任务。
原因：审校结果会写入当前任务自己的人工状态，必须持续显示任务身份，避免把修改保存到错误任务。
操作步骤：查看页面顶部的封面、标题、频道、完成时间和必审数量；在“切换已完成任务”下拉框选择目标任务。已归档但已完成的任务也可以在这里继续审校，不必回到工作台。

Q为什么有些提示是深蓝色并带黄色边框？

现象：页面上的完成、待确认、错误和永久删除操作使用了不同的蓝黄组合与符号。
原因：字幕交付和删除属于高影响操作，不能只依赖颜色区分。蓝色对勾表示已完成，黄色感叹号表示还需确认，深蓝色配黄色双边框和叉号表示错误或永久操作。
操作步骤：先阅读提示标题和具体说明；遇到黄色感叹号，先完成风险审校；遇到叉号提示，按提示修复或重试；点击带叉号的删除按钮前，确认任务或术语确实不再需要。

Q任务可以暂停、删除或只清理视频吗？

可以。任务详情提供暂停、继续和删除；完成后还能“清理源媒体但保留字幕”或“清理技术文件”。暂停、取消或强制停止会立即丢弃尚未使用的 Cookie；已经交给下载进程的临时文件会在进程退出路径统一删除。为避免重用旧登录凭据，继续需要认证的下载时请重新粘贴 Cookie。
